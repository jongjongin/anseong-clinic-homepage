# 독립 교차 검토 지침

안성경희365한의원 홈페이지 건강정보 글 초안(게시 전)을 처음 보는 검토자로서 의학·제도 사실 오류를 찾습니다. ROOT: `C:/Users/doctorstation11/orca/workspaces/anseong-clinic-homepage/homepage/content/drafts/articles_20261104/`

방법
1. 담당 글(`NN_*.md`)을 먼저 읽고 **구체적 주장**(수치, 기간, 연구 설계·결과, 제도·법령, 위험·금기, 검사 기준)을 뽑습니다. `_verify_*.md` 기록은 이 단계에서 읽지 마세요. 앞선 판단에 끌려가지 않기 위해서입니다.
2. 주장을 WebSearch·WebFetch(먼저 ToolSearch `select:WebSearch,WebFetch`)로 공식 자료(정부, WHO, CDC, NHS, NIH/MedlinePlus, 학회, PubMed/Europe PMC, Crossref)와 직접 대조합니다. 글의 '참고 자료'에 적힌 문헌을 실제로 열어 그 내용이 정말 있는지도 확인합니다. 반증을 찾는 쪽으로 읽으세요.
3. 빠진 안전 신호(응급·금기)와 과장(효과 단정, 약한 근거의 강한 표현, 한의 치료가 표준 치료를 밀어내는 서술)도 봅니다.

처리
- 틀린 것은 글에서 직접 최소 수정합니다. 확인 못 하는 강한 주장은 낮추거나 뺍니다. 지어내지 마세요.
- 고친 뒤 `cd ROOT && python -I -X utf8 _tools/check_articles.py NN` 통과를 확인합니다. 금지어·가격·유사도 기준과 검사기는 건드리지 말고 표현을 바꿉니다.
- 글의 뼈대가 무너져 고쳐도 성립하지 않으면, 그 글의 `_verify_*.md` 항목의 `판정:` 줄을 `판정: 보류 (교차 검토: 사유)`로 바꿉니다(`grep -l "^## NN" _verify_*.md`로 찾기). 고칠 수 있으면 판정은 그대로 둡니다.
- 21~40번처럼 `_verify` 형식이 다른 글은 판정 줄이 없으니 기록만 남깁니다.
- 원장이 판단해야 할 문제(법적 쟁점, 실제 진료와 맞는지)는 고치지 말고 기록합니다.

기록: `_review_시작.md`(담당 묶음마다 하나). 글별로 `확인한 주장 / 근거 URL(열어본 것만) / 결과(맞음·수정·삭제·미확인)`, 수정 전후 문장. 오류가 없으면 없다고 적습니다.

금지: 담당 외 글 수정, APPROVAL.md 수정, 배포·커밋·푸시·발송·게시, 서버·워처·`C:/bridge` 운영 스크립트 수정, 환자 정보·비밀값 기록, 되묻기. 요청은 몰아치지 말고 천천히.

끝나면 한국어로 짧게 보고: 글별 수정 건수, 사실 오류 목록(전→후), 보류로 바꾼 글, 원장 판단 필요 항목, 미확인 항목.
